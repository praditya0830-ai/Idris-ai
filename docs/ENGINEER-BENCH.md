# The engineering bench behind the chat

Everything the chat states as a number comes from `ai/engineer.py` and its solvers. The model may quote
those numbers; it may not produce new ones. This page is the contract for the studio (and for Copilot's UI
track): what to send, and what comes back.

## Endpoints

| Endpoint | Purpose |
|---|---|
| `POST /engineer/solve` | `{message, given}` -> topic, claims, missing, advice, review |
| `POST /engineer/verify` | `{answer, engineering}` -> which numbers in an answer are unverified |
| `GET /engineer/materials` | the solver material table with sources |
| `POST /part-check` | the same FEA as a job: contour, displacement, safety factor, **review[]** |

## Topics

| Topic | Input (`given`) | Claims | Evidence |
|---|---|---|---|
| `fea` | `geometry` (positions+indices or `stl_base64`), plus `force_n`/`force_vector` **or** `supports[]`+`loads[]`; `material_name`, `case`, `element_size_mm` | `fea.sigma_max`, `fea.delta_max`, `fea.sf_yield`, `fea.mass`, `fea.sigma_closed_form` | 3 (solver), 2 (cross-check) |
| `beam` | span, load, section, material | M, σ, δ, SF | 2 |
| `column` | length, section, material, end condition | Pcr (Euler/Johnson), λ | 2 |
| `bolt` | size, class, K | At, Fi, torque, separation load | 2 |
| `thermal` | length, ΔT, α, E | ΔL, σ_thermal | 2 |
| `gear` | `mn, z1, z2, b, torque_1_nm, n1_rpm, K_Hbeta, sigma_Hlim1` | σ_H1, σ_HP1, S_H1, S_H2, F_t, u | 2 (ISO 6336-2 Method B) |
| `chem` | formula / concentration / n,T,p,V | molar mass, pH, ideal gas | 2 |
| `math` | `expr` | the value | 2 |

Nothing is defaulted. A missing input appears in `missing` as `{input, unit, why}` and the topic returns no
claims. That is the intended answer to "berapa kuat?" without a load.

## Claim shape

```json
{"id": "fea.sigma_max", "label": "peak von Mises stress", "value": 48.8283, "unit": "MPa",
 "formula": "FEM: hex8 voxel model, static linear", "inputs": {"force_N": 200.0},
 "source": "physics/part_fea.py", "evidence": 3, "evidence_name": "numerical solver"}
```

Evidence: 1 = AI estimate, 2 = closed-form/standard calculation, 3 = numerical solver.

## Checks and review

`checks[]` are pass/fail verifications of the solve itself (`fea.mesh_matches_volume`,
`fea.equilibrium`, `fea.below_yield`). `review[]` (from `ai/review.py`, shared by `/part-check`) are the
findings an engineer would raise, each with the measured value:

| Code | Rule | Example message |
|---|---|---|
| `MEMBER_SLENDER` | longest/shortest bounding dimension > 40 | "the part is 67:1 (200 x 3 x 3 mm); check deflection, not only stress" |
| `WALL_THIN` | mean wall thickness 2V/S < 1.5 mm | "mean wall thickness 2V/S = 0.90 mm is below 1.5 mm" |
| `UNSUPPORTED` | \|R + F\| / Σ\|F\| > 1 % | "reaction and load differ by 21.0 %; the model is not in equilibrium" |
| `NO_LOAD_PATH` | force declared, zero stress and zero deflection | "200 N was declared but the part shows neither stress nor deflection" |
| `MESH_COARSE` | voxel volume error > 5 % | "voxel volume is off by 39.5 %; refine the element size" |

## What the studio should send

`given.geometry` from the kernel (the same mesh `/part-check` already accepts) plus the real `supports` and
`loads` selectors. With those, the chat solves the model the engineer built instead of a named cantilever,
and the answer carries the same `review[]` the Simulate tab shows.

## Known limits

- Voxel FEA: stair-stepped curved faces; peak stress at sharp corners and supports is mesh dependent — read
  `von_mises_p995_MPa` and the convergence study for sign-off.
- Supports are fully clamped; loads are spread evenly over the selected area.
- `gear` rates pitting only (ISO 6336-2); tooth-root bending is a separate check.
- The chat text itself is generated by the LLM; only the numbers are gated. A live LLM end-to-end test needs a
  provider key on the server and has not been run in CI.
